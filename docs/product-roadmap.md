# SCRM 产品规划

> 定位：**多渠道私域 CRM 中台**。以 CRM 销售域为核心，企微/小红书/公众号/抖音为渠道，统一客户主档 + 营销获客 + 销售管线。
> 对标：销售域 → 微盛·企微管家 / 探马 SCRM；多渠道统一 → 群脉 / 数云；营销活动 → 小裂变 / 有赞。

## 一、产品定位与差异化

| 维度 | 传统 SCRM（微盛/探马） | 多渠道中台（群脉/数云） | 本产品 |
|------|----------------------|----------------------|--------|
| 核心 | 企微 SCRM | 公私域统一客户主档 | **CRM 销售域为核心，渠道为可插拔维度** |
| 客户主档 | 企微 external_userid 为主键 | 统一 OneID | 本地 ID 主键 + ChannelLink 渠道映射（企微 ext id 降级为渠道外部键） |
| 渠道 | 仅企微 | 企微+公域多渠道 | 企微已通，小红书/公众号/抖音预留并逐步接入 |
| 销售管线 | 弱（重运营轻销售） | 弱 | **强**（线索→商机→阶段→订单，完整 funnel） |
| 营销活动 | 企微群发/欢迎语/活码 | 全渠道营销自动化 | 企微运营已通 + 营销活动骨架（coupon/lottery/seckill/h5） |

**差异化抓手**：竞品要么"重运营轻销售"（SCRM），要么"重中台轻执行"（私域中台）。本产品把**销售管线**和**多渠道获客**放在同一张图上——销售要的是 funnel 和业绩，运营要的是触达和转化，两者共享同一份客户主档。

### 架构预留的扩展点
- `CrmCustomer.Source` / `CrmActivity.Channel` / `ChannelLink.Channel`：同一套渠道常量（wecom/xiaohongshu/gzh/douyin/general），新增渠道只加常量 + 适配器，不动主档
- `ChannelLink`：本地实体 ↔ 渠道外部 ID 映射，企微 ext id 已降级为渠道外部键
- `CrmChannelInteraction`：非企微渠道行为数据（留资/评论/私信）统一落库
- `dispatch` 注册表：新增业务动作只需 `Reg.Register("域","动作",handler)`

## 四、技术原则（贯穿各阶段）

1. **渠道无关优先**：CRM 核心域（crm_*）不依赖任何渠道字段，渠道数据经 ChannelLink 桥接。新增渠道 = 加常量 + 适配器，不动主档。
2. **本地身份为顶层数据分区**：tenant_id 是所有 CRM 表的分区键，企微 corp_id 降级为渠道维度。多租户 SaaS 天然支持。
3. **闭源核心 + 开放网关**：业务逻辑在 scrm-server（gRPC :9002），HTTP/鉴权在 gateway（:9001）。新业务动作走 dispatch 注册表，不改契约。
4. **种子幂等**：默认角色/阶段/渠道标签按 (tenant_id, channel) 幂等补齐，存量租户只补缺失项。
5. **回调驱动同步**：企微/小红书数据以回调事件为准同步进 CRM 主档，API 补全为辅（失败仅 log 不阻塞）。

## 五、优先级排序依据

- **Phase 1 先于 Phase 2**：销售域是差异化抓手，若 funnel 不可信，多渠道获来的客户也守不住。先让销售用起来。
- **Phase 2 先于 Phase 3**：多渠道是核心承诺，需尽早验证 ChannelLink 架构。营销活动骨架已存在，不阻塞。
- **Phase 3 在渠道验证后**：营销活动要投放到渠道上，渠道通了活动才有载体。
- **Phase 4 在基础闭环后**：自动化是锦上添花，前提是数据闭环已形成。
- **Phase 5 按需**：公众号/抖音复用已验证架构，业务需要时再接。
