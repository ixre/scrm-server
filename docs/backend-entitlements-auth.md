# 后端套餐、权限与账号安全

升级时先在 `scrm-server` 中执行 `go run ./cmd/migrate -schema-only`，再配套更新 core、gateway、dashboard 和 msg-server。新增迁移为 0031–0034，分别安装配额约束、迁移 CRM 权限点、安装账号会话版本与迁移平台权限点。core 检查这四项迁移，缺失时拒绝启动，避免只升级 Go 模型后遗漏数据库约束。

旧 JWT 没有会话版本，升级后需要重新登录。网关和 core 的内部签名均覆盖会话版本，必须配套发布。生产反向代理需保留公开的 Host，并配置可信代理 IP；生产网关使用 release 模式或 `CRM_COOKIE_SECURE=true`。Cookie 认证的写请求及密码登录只允许同源浏览器请求。

## 套餐权益

- 每次业务调用从数据库读取当前租户套餐，先校验模块，再校验账号权限。未映射的新业务服务默认拒绝；账单、续费、当前账号、改密和退出保留必要入口。
- 企业停用或套餐到期后禁止业务访问；试用/限期免费套餐到期自动降级为默认永久免费版，付费套餐到期仍拦截并引导续费（402）。套餐本身停用表示停售，已有租户继续使用其有效订阅；删除被租户使用的套餐仍被禁止。
- 有效配额取套餐限制与租户正数限制中较小者，0 表示该层不另设上限。租户不能通过填写 0 或更大的数字绕过套餐限制。
- 用户数按未删除且启用的本地账号计算，包含管理员。客户数包含全部未删除客户，包括公海和流失客户。存量超额数据保留，禁止继续增加占用。
- 数据库触发器对所有写入生效，覆盖并发新增、导入、转换、同步、启用账号及恢复客户。更新已有记录和释放占用不要求先降到配额以内。
- 渠道配置分别校验渠道模块；开启会话存档还需 `msg_archive`。msg-server 自身的读取入口及同步企业发现也校验租户状态、到期时间、企微模块、存档模块与存档开关。
- 公开名片与落地页从页面所属租户校验套餐；公开获客提交还需相应线索、客户模块。企微事件、企微周期同步及相关 CRM 自动任务同样检查套餐。
- 公海自动回收在每批事务前重新检查客户模块；即使任务运行期间移除模块，也会停止后续批次，保留已提交批次的数据与审计记录。

## 权限点

租户权限读取 `crm_role.perms`，平台权限读取 `platform_admin.perms`。角色编码只用于标识、展示和选择初始化预设，不再在请求期间授予权限。0032、0034 将现有内置角色的能力转换为持久化授权；之后修改权限点即可生效，不需要修改角色名称或重新签发 JWT。

租户权限格式为 `crm:<业务资源>:<动作>`，例如 `crm:user:create`、`crm:user:set_password`、`crm:customer:read`、`crm:customer:write`。普通读写支持资源的 `read`、`write`、`full`，敏感管理动作另检查具体权限点。`crm:*:full` 为租户完整管理权限；`crm:data:all` 扩大租户内数据范围，仍需相应操作权限。风控接口使用 `crm:risk:*`。企微独立会话校验企业内角色实际保存的 `Biz…_Read/Full` 权限，不依赖角色类型名称。

批量操作、回收站和自定义字段还检查实际目标对象的套餐与权限；线索转客户、报价转订单另需目标对象的创建权限。回收站列表隐藏无权读取或未购买模块的对象。自定义字段的读写继承父记录的归属范围，写入与父记录加锁在同一事务完成，不能通过字段接口修改其他销售的数据。字段定义的业务类型和标识创建后不可改绑。

自动分配规则按实际客户或线索类型校验模块和 `crm:<实体>:assign`（或该实体 `write`、`full`）权限；改绑规则需同时具有原类型和新类型的授权。列表隐藏未购买或无读取权限的实体规则，执行记录另需客户读取权限。配置管理权限和全租户数据范围不会单独授予目标实体的分配权限。

平台权限格式为 `platform:<资源>:<动作>`，例如 `platform:tenant:list`、`platform:tenant:reset_admin_password`、`platform:admin:create`。同样支持资源 `read`、`write`、`full` 和 `platform:*:full`。平台账号创建、修改与重置密码也检查授权范围，不能借账号管理权限获取更高权限。

CRM 原生角色接口经 `/api/v1/biz/` 访问：

- `crm_role/List`：读取本租户角色，需要 `crm:role:read`。
- `crm_role/Create`、`crm_role/Update`：请求字段为 `code`、`name`、`perms`，更新另传 `id`；需要 `crm:role:manage`，只能授予自身已有的权限。
- `crm_role/Delete`：传 `id`，仍有账号使用的角色不可删除。
- `crm_user/RoleOptions`：返回操作者可以分配的角色；员工表单使用真实角色 ID，支持自定义角色。

创建、编辑角色还需套餐包含 `role_perm`。不能修改自己正在使用的 CRM 角色，需由另一位授权管理员操作。更换账号角色、管理更高权限账号及停用最后一个管理员均受后端保护。平台账号创建、更新可传 `perms` 数组；未指定时，新账号使用所选角色的初始化预设，更新同名角色时保留既有自定义权限。

## 账号与会话

本地账号、平台账号及企微员工持有单调递增的 `auth_version`。JWT 携带对应版本，core 每次认证请求从数据库复核。改密、密码重置、停用、删除及适用的角色变更会使旧版本失效；退出接口撤销该账号全部会话，再清除 HttpOnly Cookie。租户到期、停用时仍可退出。恢复账号不会恢复旧令牌。

JWT 使用固定 24 小时有效期，取消自动滑动续期。登录校验采用统一失败提示；登录预算由 Redis 在实例间共享，同时限制来源 IP 和跨 IP 的同一账号尝试。限流依赖不可用时拒绝登录。

通用 `/api/v1/biz/:service/:action` 路由的 GET、HEAD 仅接受已列入白名单的读取动作；退出、删除、改密等动作必须使用 POST、PUT、PATCH 或 DELETE，不能借 GET 绕过 Cookie 写请求的同源校验。新动作默认需要写请求方法；OPTIONS 不执行业务动作。

头像上传、上传地址签发等由网关直接处理的受保护接口也向 core 复核账号与会话版本，避免本地处理接口继续接受已吊销令牌。前端退出会调用后端撤销会话，再清理本地登录状态。

新建和重置密码要求 10–64 字节、同时包含字母和数字；随机初始密码遵循同样规则。已有密码不会被自动更改。用户自助改密必须验证本人旧密码，且不能覆盖并发更新后的密码。

不再自动创建固定弱密码账号。DEV/TEST 环境只有显式设置符合要求的 `CRM_BOOTSTRAP_ADMIN_PASSWORD` 或 `CRM_DEMO_ADMIN_PASSWORD` 时，才分别创建 `master` 平台账号或 `demo/admin` 演示账号。其他环境不创建这些开发账号。

开发强制登录还需显式设置 `CRM_ENABLE_FORCE_LOGIN=true`，生产环境始终禁止。企微登录返回地址限制为本站路径，拒绝外站、协议相对地址和混淆斜杠。

## 验证

使用隔离 PostgreSQL 和 Redis 验证模块拒绝、租户隔离、并发配额、恢复与启用、原生及平台自定义权限、越权授权、最后管理员保护、会话吊销、分布式登录限流和实际迁移执行。网关测试覆盖签名中的会话版本、防跨站 Cookie 写请求与取消自动续期；dashboard 执行 TypeScript、生产构建和请求契约测试。
