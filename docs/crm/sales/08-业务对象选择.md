# 客户与合同的检索和关联

## 产品任务与范围

销售新增商机、报价或合同时，需要找到更早录入的客户。财务维护回款计划、筛选回款时，需要找到历史合同。旧页面只加载前 500 条并在浏览器过滤，数据增加后无法完成这些任务，加载失败也容易误认为没有业务对象。

按 product-manager-toolkit 的 JTBD 与 MoSCoW 方法，本轮优先完成核心商机、报价、合同、回款计划和回款工作台的选择器，同时修正商机列表、详情和管线看板的客户名称回显。依据为现有代码与回归场景，没有虚构用户访谈或 RICE 收益数据。扩展模块及产品等其他字典的旧选择器另行验收。

## 使用规则

- 打开下拉后远程读取，每页默认 50、最多 100 条；“加载更多”使用 ID 游标，不全量下载、不计算选项总数。输入后延迟 250 毫秒检索。
- 客户按名称、公司、手机号开头查找；合同按名称、合同号开头查找。也支持完整数字 ID 精确查找。英文大小写不敏感，`%`、`_`、反斜线视为普通字符。
- 创建销售业务仅提供本人负责或主管有权管理、已领取且已接收的客户。共享可读客户不能因此获得新增业务权限。查询筛选使用客户原有可读范围。
- 回款计划只提供当前有权操作且未作废的有效状态合同，授权以合同销售归属为准。客户转交不改变合同授权。计划客户自动取合同客户，编辑已有计划不能更换合同。
- 历史已选项独立按 ID 读取，不受当前搜索或首屏影响。可读但不能再新增关联的项保留名称并禁用；已删除、跨租户或已无权读取的项仅显示 ID 和不可用提示，不返回名称。
- 检索和名称解析失败明确显示重试入口，旧搜索/关闭后返回的响应不覆盖当前结果。列表名称只解析本页 ID，每次最多 100 个，失败时保留 ID 供核对。

本轮不新增黑名单业务规则，销售写入仍以现有服务校验为准；选项不是授权凭证，保存时继续重新鉴权与校验。报价商机的 100 条上限及管线的 1000 条上限已由 0026 补齐，见 [商机与管线](02-商机与管线.md)；扩展模块和其他字典仍需分期处理。

## 接口契约

`POST crm_customer/Options` 与 `POST crm_order/Options`：

| 字段 | 约定 |
| --- | --- |
| `purpose` | 默认 `read`；客户另支持 `sales`，合同另支持 `plan`，无效用途报错 |
| `keyword` | 最多 128 字符，修剪首尾空白，按上述字段前缀查询 |
| `cursor` | 绑定租户、操作人、对象类别、用途及检索词，切换范围需重新查询 |
| `page_size` | 默认 50，最大 100 |
| `ids` | 独立解析至多 100 个正整数 ID，不能与搜索/游标混用，重复项去重 |

返回 `{items:[{id,label,disabled,customer_id?}],has_more,next_cursor}`。已选值解析无下一页，只返回当前可读记录。查询设 5 秒上下文超时，每次验证有效账号及当前权限。游标不授予权限，权限撤销后继续翻页也不会泄露记录。客户标签仅含名称/公司回退值及手机号，合同标签含名称/ID 回退值和合同号，不传完整主档。

## 数据库与升级

迁移 `0025_business_object_options.sql` 仅增加 9 个索引：客户/合同各自的租户游标与负责人游标，以及客户名称、公司、手机号和合同名称、单号的租户前缀表达式索引。复用既有共享可见范围及主键，无新表、字段、物理外键或历史回填。AutoMigrate 复用同份索引 DDL。

升级顺序为备份 → 恢复副本 → 版本迁移 → AutoMigrate → 重复版本迁移 → 核对全表内容 → 本地正式库迁移 → core/dashboard。普通建索引可能阻塞写入，生产大表需要维护窗口，并测量磁盘、写放大和构建时间；不能把索引及分页等同于千万行多租户容量验收。
