# 报价单

销售通过报价确认方案、金额和有效期；客户接受后，可生成合同草稿并在合同中办理签约。入口为“销售管理 → 商务合同 → 报价单”。主模型 `CrmQuote` 位于 `app/models/crm_sales_models.go`。

## 字段与流程

| 字段 | 规则 |
| --- | --- |
| `customer_id` | 必选，当前有权操作且已领取、已接收的客户 |
| `opportunity_id/contact_id` | 可选，必须属于当前客户，商机还须具有操作权限 |
| `subject` | 报价主题，必填；不是 `title` |
| `quote_no` | 租户内唯一，留空由日期及全局 ID 生成 |
| `amount/discount/final_amount` | 金额、优惠金额、最终金额；优惠不是折扣比例，不能超过金额，最终金额由服务端计算 |
| `items` | 报价明细，沿用现有服务字段 |
| `valid_until` | 有效期，可空，发送和接受时按中国日历校验 |
| `owner_user_id` | 归属销售，普通销售不能指定他人 |
| `status/order_id` | 服务端维护生命周期和转合同回链，不能由普通编辑跳过流程 |

新建使用 `crm_quote/Create`，先存 `draft`；只有草稿可以 `Update`。`ChangeStatus` 支持 `draft → sent → accepted/rejected`，草稿及已发送报价可通过 `Void` 填原因作废。不会自动创建文档中不存在的 `completed/expired` 状态，也不宣称已实现定时过期提醒。

`ConvertToOrder` 已实现：仅已接受的报价首次转为合同草稿；事务锁定报价、验证金额与关联、创建合同并保存 `order_id`。重复请求返回同一合同，不重复创建。生成草稿不等于已签约或自动发送客户消息。报价最终金额成为合同金额，主题成为合同名称，保留客户、商机及来源报价说明；后续在合同中办理签约和回款。

`List` 支持客户、商机、状态及关键词筛选；负责人范围与写入检查一致。`Transfer/BatchTransfer` 为独立交接操作，不通过普通编辑绕过授权。

## 关联客户和商机（0025/0026）

客户使用远程检索和独立已选 ID 解析，不受旧前 500 条缓存限制。选择客户后，通过 `crm_opportunity/Options` 按客户范围查询商机，支持名称前缀/完整 ID、游标和历史已选项解析，解除旧前 100 条限制。共享可读客户不自动获得新增报价权限，其他客户/销售/租户的商机不会混入。

更换客户清除旧商机和联系人；未选客户时商机选择器禁用。异步结果绑定当前客户和检索词，旧请求不会覆盖新客户选项。客户转交后，仍可读的旧商机仅保留历史回显、禁用新关联，保存时继续由服务端验证。

搜索、分页、已选值读取失败提供重试。完整协议和迁移见 [业务对象选择](08-业务对象选择.md) 和 [商机与管线](02-商机与管线.md)。

## 验收边界

本轮验证 605 条客户商机全部可达、旧记录找回、当前客户与归属范围、游标范围、已选值独立回显及客户转交/软删除后重新鉴权。未把 PDF 输出、报价版本对比、审批流、到期提醒和真实浏览器完整任务认定为已完成；这些能力应按实际销售流程继续分期。
