# 商机与销售管线

## 目的
管理从"初步接洽"到"合同签订"的完整销售过程，可视化销售漏斗。

## 入口
- 销售管理 → 线索商机 → 商机
- 销售管理 → 线索商机 → 销售管线

## 数据模型

### CrmPipelineStage（销售阶段）
`models/crm.go:166-176`：

| 字段 | 说明 |
|------|------|
| `name` | 阶段名 |
| `sort` | 排序 |
| `probability` | 成交概率（0-100） |
| `is_won` | 是否赢单终态 |
| `is_lost` | 是否输单终态 |

### CrmOpportunity（商机）
`models/crm.go:178-201`：

| 字段 | 说明 |
|------|------|
| `customer_id` | 关联客户 |
| `lead_id` | 来源线索 |
| `owner_user_id` | 归属销售 |
| `stage_id` | 当前阶段 |
| `title` / `product` / `amount` | 商机信息 |
| `expected_close_date` | 预计成交日期 |
| `status` | open / won / lost |
| `probability` | 成交概率 |
| `expected_revenue` | 预计收入 |
| `competitor` | 竞争对手 |
| `next_step` | 下一步行动 |
| `lost_reason` | 输单原因 |
| `product_details` | 产品明细 JSON |

## 操作步骤

### 1. 配置销售阶段

**接口**：`crm_pipeline.Create`

```json
{
  "name": "POC 测试",
  "sort": 4,
  "probability": 60,
  "is_won": false,
  "is_lost": false
}
```

**预置阶段**（租户创建时自动播种）：

```
1. 初步接洽 (10%)
2. 需求确认 (25%)
3. 方案报价 (50%)
4. 商务谈判 (70%)
5. 合同签订 (90%)
6. 已成交 (100%)
```

### 2. 创建商机

**接口**：`crm_opportunity.Create`

```json
{
  "customer_id": "1001",
  "title": "ACME 公司采购 100 套",
  "product": "SCRM 企业版",
  "amount": 500000,
  "expected_close_date": "2026-09-30",
  "stage_id": "1",
  "product_details": [
    {"name": "SCRM 企业版", "spec": "100 用户", "qty": 1, "price": 500000, "amount": 500000}
  ]
}
```

### 3. 商机阶段推进（核心操作）

**接口**：`crm_opportunity.MoveStage(id, stageID)`

**逻辑**（`services/crm.go` 的 `MoveStage` 方法）：

```go
1. 校验 stage_id 存在且属于本租户
2. UPDATE opportunity SET stage_id=?, probability=stage.probability
```

**当前限制**（**产品补强点**）：
- 无阶段顺序校验（可任意跳转）
- 跟进强制校验已实现（通过销售规则配置）
- 无并发控制

**建议补强**：
```go
// 1. 阶段顺序校验
prevStages := getPriorStages(tenantID, stageID)
if !prevStages.contains(currentStage) {
    return error("必须先经过前一阶段")
}
// 2. 跟进强制校验
if !hasFollowupInLastNDays(opportunity, 7) {
    return error("7 天内需要有跟进才能推进阶段")
}
```

### 4. 批量阶段推进

**接口**：`crm_opportunity_ext.BatchChangeStage(tenantID, ids, stageID)`（**待实现**）

### 5. 赢单

**接口**：通过 `crm_opportunity.MoveStage` 移动到赢单终态阶段实现

**逻辑**：
- `status = won`
- `won_at = now`
- `won_at` 时清空 `lost_at, lost_reason`

**联动**：可触发"赢单 SOP"（发庆祝邮件 / 创建订单待办）。

### 6. 输单

**接口**：通过 `crm_opportunity.MoveStage` 移动到输单终态阶段实现

**逻辑**：
- `status = lost`
- `lost_at = now`
- `lost_reason = 客户选择竞品`

**输单原因字典**：建议在 CrmDict 中维护（"价格太高""功能不匹配""竞品优势""决策人变动"等）。

### 7. 查询商机

**接口**：`crm_opportunity.Query`

支持过滤：
- `customer_id`
- `owner_user_id`
- `stage_id`
- `status`

### 8. 销售漏斗（看板视图）

**接口**：`crm_report.PipelineFunnel(tenantID)`

返回按 `stage_id` 分组的：
- 商机数
- 商机总金额
- 加权金额（amount × probability）

## 阶段推进流程

```
new Lead ──► CreateOpportunity ──► Stage 1(初步接洽)
                                          │
                                          ▼
                                     Stage 2(需求确认)
                                          │
                                          ▼
                                     Stage 3(方案报价) ──► CreateQuote
                                          │
                                          ▼
                                     Stage 4(商务谈判)
                                          │
                                          ▼
                                     Stage 5(合同签订) ──► CreateOrder
                                          │
                                          ▼
                                     Stage 6(已成交) ──► Win()
                                                      ──► CreateReceivables
```

## 注意事项

- **阶段自定义**：租户可自定义阶段（增删改），不影响历史商机。
- **金额实时更新**：商机金额变化会同步到漏斗统计。
- **赢率自��**：阶段切换时 probability 自动同步为阶段的默认值（可手动覆盖）。
- **删除限制**：已赢/已输的商机不可删除，仅能修改备注。
- **关联绑定**：商机必须关联客户（强校验）。
