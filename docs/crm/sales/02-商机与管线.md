# 商机与销售管线

## 产品任务及本轮范围

销售需要找到所有进行中的商机、按负责人和预计成交日期判断管线规模，并将商机推进到下一阶段。旧看板只读取前 1000 条，然后在浏览器筛选日期、计算数量和金额，会漏看历史商机并低估管线。本轮按 product-manager-toolkit 的 JTBD 与 Must 优先级完成服务端完整汇总、各阶段分页、历史异常阶段展示及阶段关闭校验。证据来自现有实现与数据库回归，没有虚构访谈和 RICE 收益。

入口为“销售管理 → 线索商机 → 商机/销售管线”。模型位于 `app/models/crm_sales_models.go`，使用租户及标量 ID 关联，无新增物理外键。

## 商机与阶段规则

- 商机必须关联当前有权操作且已领取、已接收的客户；普通销售管理本人商机，主管/管理员管理本租户范围。共享客户可读不意味着可管理其商机。
- 新建商机为 `open`，不能直接创建为赢单或输单。未指定阶段时使用第一个非终态阶段；无阶段配置的历史商机仍能在看板找到。
- 普通 `MoveStage`、`ChangeStage`、`BatchChangeStage` 和编辑入口只能推进非终态阶段，执行租户的最近跟进校验；事务锁定当前商机，批次失败整体回滚。
- 赢单使用 `crm_opportunity/Win`，填写 `won_reason/actual_amount`；输单使用 `Lose`，填写 `lost_reason`。二者校验原因、当前状态、阶段配置和跟进规则，保存状态及历史。拖到终态列时界面打开详情办理专用操作。
- 已关闭商机须先 `Reopen` 才能编辑或推进，恢复时清除关闭字段；已有跟进、报价、合同的商机不能直接删除。
- 阶段概率用于推进时更新商机概率及预计收入。本轮看板加权金额按各商机已保存的 `probability` 汇总，再统一保留两位小数；调整阶段配置不会凭空改写历史商机。

不强制逐阶段顺序推进；是否支持必经阶段、字段校验和审批需要另行明确业务规则。

## 管线看板

### 完整汇总

`POST crm_opportunity/Board` 接收：

```json
{"owner_user_id":"10","date_from":"2026-10-19","date_to":"2026-10-19"}
```

字段可全部省略。日期需成对提交有效 `YYYY-MM-DD`，开始不得晚于结束。按中国时区完整日历日过滤 `expected_close_date`，结束日包含到当天最后一刻；未填写预计日期的商机仅在不筛日期时出现。筛选、重置和刷新使用明确的当前范围，不在浏览器截取后过滤。

返回 `columns/as_of`。每列包含阶段资料、完整筛选范围的 `count/amount/weighted_amount`，以及默认 20 张卡片的 `items/has_more/next_cursor`。金额均为十进制字符串，避免大额汇总丢分。首屏汇总与首屏卡片处于同一只读一致性快照，页面显示读取时间，不以已加载卡片数计算总额。

NULL、阶段已删除及未知阶段统一进入 `stage_id="unassigned"` 的“待配置阶段”列；其他租户的阶段资料不会返回。该列可作为恢复处理来源，不能作为拖入目标。配置最多读取 100 个阶段，超出时明确报错，不静默截断。

### 分页及并发变化

`POST crm_opportunity/BoardPage` 接收与汇总相同的筛选字段，另带 `stage_id/cursor/page_size`。默认 20、最大 100 张卡片，按 ID 降序翻阅，无 OFFSET。游标绑定租户、操作人、负责人和日期范围、阶段及阶段配置集合。每页重新校验权限；阶段集合变化需刷新，转交、关闭、软删除及跨租户记录不会绕过当前权限。

分页不持有跨 HTTP 请求的数据库快照。其他人移动或删除商机后，后续卡片可能与首次汇总读取时间不同；刷新重新取得一致的汇总和首屏。旧筛选/已关闭页面返回的请求不会覆盖当前状态。读取失败提供重试，单列翻页失败保留当前卡片及原游标。

### 旧报表兼容

旧 `crm_report/PipelineFunnel`、`PipelineInspection` 同步增加有效账号和负责人范围检查，普通销售不能通过空负责人或提交他人 ID 获取团队汇总。旧报表仍保留既有数字金额响应；本轮未将所有报表改为十进制字符串，也未完成所有仪表盘口径验收。

## 报价关联商机

`POST crm_opportunity/Options` 必须带 `customer_id`。用于报价时传 `purpose="quote"`，支持名称前缀或完整 ID 检索、50/100 的选项分页、至多 100 个 `ids` 独立解析。只返回本人或主管可管理且属于所选客户的商机。旧已选值不受前 100 条限制，客户转交或待接收后历史可读项保留回显并禁用新关联；更换客户会清除旧商机和联系人。

商机 `open/won/lost` 的可关联规则沿用现有报价服务，不新增隐含状态限制。检索和已选解析都有失败重试，服务端仍在报价保存时验证关联。

## 数据库及升级（0026）

`0026_opportunity_bounded_reads.sql` 新增 5 个索引：租户/客户/商机名称前缀，以及仅有效 `open` 商机的阶段游标、负责人阶段游标、预计日期、负责人预计日期。游标索引携带汇总所需的金额、概率及日期等字段。AutoMigrate 共用同份 DDL，无新字段、表、历史回填或物理外键。

先备份，在恢复副本执行版本迁移 → AutoMigrate → 重复版本迁移，并核对全部业务表内容，再升级本地库及 core/dashboard。普通建索引可能阻塞写入，生产需维护窗口并测量索引大小、写放大及构建耗时。汇总仍需扫描当前权限和日期范围内的有效索引，5 秒分页及 10 秒汇总超时不等于千万行负载 SLA。
