# 工单（Workorder）

## 目的
为客户提供售后服务、技术支持、投诉处理等的任务跟踪。

## 入口
- 客服 → 工单管理
- 客户 → 报修入口（公众号菜单/H5）
- 售后 → 转工单

## 数据模型

`CrmWorkorder`（`models/crm.go:1327-`）：

| 字段 | 说明 |
|------|------|
| `workorder_no` | 工单号 |
| `customer_id` / `contact_id` | 关联客户/联系人 |
| `type_id` | 工单类型 |
| `source` | manual / wechat / system / aftersales |
| `title` / `content` | 工单标题/内容 |
| `priority` | 紧急度（待实现） |
| `status` | pending / assigned / processing / resolved / closed |
| `assignee_id` | 当前处理人 |
| `satisfaction` | 满意度评分（1-5） |
| `sla_response_minutes` / `sla_resolve_minutes` | SLA（**当前未实现**） |
| `response_at` / `resolve_at` | 首次响应时间/解决时间 |

`CrmWorkorderType`（工单类型）：技术问题/产品咨询/退款申请/投诉建议。

`CrmWorkorderLog`（工单日志）：操作流水。

`CrmWorkorderPool`（工单池）：未分配工单。

## 操作步骤

### 1. 创建工单

**接口**：`crm_workorder.Create`

```json
{
  "customer_id": "1001",
  "type_id": "1",
  "title": "无法登录后台",
  "content": "客户从昨天下午开始无法登录..."
}
```

**自动生成**：`workorder_no` 格式 `WO202608180001`。

### 2. 工单类型管理

**接口**：`crm_workorder_type.Create / Update / Delete / Query`

### 3. 分配工单

**接口**：`crm_workorder.Transfer(tenantID, id, toUserID)`

### 4. 状态变更

**接口**：`crm_workorder.ChangeStatus`

```json
{
  "id": "6001",
  "status": "processing"  // pending → assigned → processing → resolved → closed
}
```

### 5. 工单池

**接口**：
- `crm_workorder_pool.MoveToPool(tenantID, ids)`：放入工单池
- `crm_workorder_pool.Receive(tenantID, userID, id)`：单个认领
- `crm_workorder_pool.BatchReceive(tenantID, userID, ids)`：批量认领
- `crm_workorder_pool.ListPool(tenantID, req)`：列表

### 6. 工单日志

**接口**：
- `crm_workorder_log.Add(tenantID, workorderID, userID, action, content)`
- `crm_workorder_log.ListByWorkorder(tenantID, workorderID)`

**示例**：每次状态变更自动添加日志：

```
"李四 处理了 工单 #6001"
"工单 #6001 已分配给王五"
"工单 #6001 已关闭"
```

### 7. 满意度评价

**当前**：字段存在但无入口。

**建议补强**：
- 工单关闭后自动发满意度调研链接（企微/短信）
- 客户评分后回写 satisfaction 字段
- 满意度低于 3 星自动升级到主管

## 工单状态机

```
pending（待分配）
   │
   ▼
assigned（已分配）
   │
   ▼
processing（处理中）
   │
   ▼
resolved（已解决）
   │
   ▼
closed（已关闭）
   │
   └──► reopened（重开）
```

## SLA（**当前未实现，建议补强**）

**典型配置**：
- 紧急工单：30 分钟响应，4 小时解决
- 普通工单：2 小时响应，24 小时解决
- 低优先级：8 小时响应，72 小时解决

**实现方案**：
1. `CrmWorkorderType` 增加 `sla_response_minutes`、`sla_resolve_minutes`
2. 工单创建时记录 `sla_deadline_response`、`sla_deadline_resolve`
3. 定时任务扫描超时工单，触发告警
4. 仪表盘展示 SLA 达成率

## 自动派单（**当前未实现，建议补强**）

**建议**：
1. 工单池规则：按"技能匹配 + 负载最低 + 部门"自动派单
2. 创建 `CrmAutoDispatchRule` 表
3. 工单进入池后 5 分钟内未手动认领，触发自动派单

## 注意事项

- **客户视角**：客户只能看自己的工单，跨客户禁止。
- **团队协作**：可加评论（建议 `CrmWorkorderComment`）。
- **附件**：建议加 `CrmWorkorderAttachment`（截图/合同/发票照片）。
- **字段映射**：工单可加自定义字段（`CrmFieldDef`）。
- **跨租户禁止**。
- **当前缺口**：
  - ❌ 无 SLA 模型
  - ❌ 无自动派单
  - ❌ 无满意度调研入口
