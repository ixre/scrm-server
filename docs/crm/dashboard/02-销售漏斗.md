# 销售漏斗

## 目的
按商机阶段统计转化漏斗，找出薄弱环节。

## 入口
- 工作台 → 数据看板 → 销售漏斗

## 数据模型

商机 6 个默认阶段：

| 阶段 | 含义 |
|------|------|
| 新建线索 | 初步接触 |
| 资格确认 | 验证需求/预算 |
| 方案报价 | 提供方案 |
| 谈判中 | 商务谈判 |
| 成单 | 成交 |
| 输单 | 失败 |

## 接口

**接口**：`crm_report.PipelineFunnel(tenantID, dateRange)`

`services/crm.go:1561 PipelineFunnel` 已实现。

```json
{
  "rows": [
    {"stage": "新建线索", "count": 100, "amount": 5000000, "conversion": 100.0},
    {"stage": "资格确认", "count": 60, "amount": 3000000, "conversion": 60.0},
    {"stage": "方案报价", "count": 30, "amount": 1800000, "conversion": 30.0},
    {"stage": "谈判中", "count": 15, "amount": 900000, "conversion": 15.0},
    {"stage": "成单", "count": 8, "amount": 500000, "conversion": 8.0},
    {"stage": "输单", "count": 5, "amount": 200000, "conversion": 5.0}
  ]
}
```

## 漏斗图

前端 G2Plot 漏斗图，按 stage 顺序绘制。

## 转化率计算

```go
conversion[i] = count[i] / count[0] * 100
```

## 按维度筛选

```json
{
  "filters": {
    "owner_id": "2001",
    "department_id": "100",
    "channel": "wecom",
    "date_range": "2026-08-01 to 2026-08-18"
  }
}
```

## 阶段停留时长

**接口**：`crm_report.StageDuration(stageID)`

每个商机在当前阶段平均停留天数（识别卡点）。

## 输单原因

**接口**：`crm_report.LostReasons`

按 `lost_reason` 字段聚合。

## 注意事项

- **权限**：漏斗数据受 data_scope 控制（销售仅看自己，主管看团队）。
- **时间窗口**：默认最近 30 天，可调整。
- **T+1**：阶段数据通常 T+1 同步，**实时性弱**。

## 当前限制（**产品补强点**）

- 无按客户行业 / 来源拆分漏斗。
- 无预测（本月预计成单）。
