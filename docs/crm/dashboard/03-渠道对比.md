# 渠道对比

## 目的
对比不同渠道（企微/小红书/公众号/抖音）的获客、转化、GMV 表现。

## 入口
- 工作台 → 数据看板 → 渠道对比

## 接口

### 1. 渠道汇总

**接口**：`crm_report.ChannelSummary(tenantID, dateRange)`

`services/crm.go:1602 ChannelSummary` 已实现。

```json
{
  "rows": [
    {
      "channel": "wecom",
      "new_customers": 100,
      "interactions": 5000,
      "orders": 50,
      "gmv": 100000,
      "conversion_rate": 5.0
    },
    ...
  ]
}
```

### 2. 渠道对比

**接口**：`crm_report.ChannelCompare(tenantID, dimension, dateRange)`

`services/crm.go:1664 ChannelCompare` 已实现。

```json
{
  "dimension": "new_customers",
  "by_channel": [
    {"channel": "wecom", "value": 100, "ratio": 50.0},
    {"channel": "xiaohongshu", "value": 60, "ratio": 30.0},
    {"channel": "gzh", "value": 40, "ratio": 20.0}
  ]
}
```

**dimension**：

| dimension | 含义 |
|-----------|------|
| new_customers | 新增客户数 |
| interactions | 互动数 |
| orders | 订单数 |
| gmv | GMV |
| conversion_rate | 转化率 |

## 渠道漏斗

```go
曝光 → 互动 → 加好友 → 下单
```

每个渠道独立漏斗：

```json
{
  "wecom": {
    "exposure": 10000,
    "interaction": 5000,
    "add_friend": 800,
    "order": 50
  },
  "xiaohongshu": {
    "exposure": 50000,
    "interaction": 8000,
    "add_friend": 200,
    "order": 30
  }
}
```

## ROI 分析

```json
{
  "wecom": {"cost": 5000, "gmv": 100000, "roi": 20.0},
  "xiaohongshu": {"cost": 8000, "gmv": 50000, "roi": 6.25}
}
```

ROI = (GMV - 成本) / 成本

**注意**：成本数据需从广告平台导入（**当前未对接**）。

## 跨渠道归因

**接口**：`crm_report.MultiTouchAttribution(customerID)`

**当前未实现**（**产品补强点**）：识别客户旅程的多个触点对成交的贡献。

## 注意事项

- **去重**：跨渠道客户去重，避免重复统计。
- **主渠道归因**：默认归到 `is_primary=true` 的渠道。
- **跨渠道成交**：客户加好友在 A 渠道，下单在 B 渠道，**归到主渠道**。

## 当前限制（**产品补强点**）

- 无广告成本对接。
- 无跨渠道归因。
- 无实时渠道看板。
