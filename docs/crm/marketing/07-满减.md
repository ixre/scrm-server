# 满减

## 目的
订单满 X 元减 Y 元，刺激客单价提升。

## 入口
- 工作台 → 营销中心 → 满减
- 订单创建时自动核销

## 数据模型

`CrmFullReduction`（`models/crm.go:610-`）：

| 字段 | 说明 |
|------|------|
| `name` | 满减规则名 |
| `tiers` | 阶梯规则 JSON：`[{threshold, reduction, max_reduction_count}]` |
| `start_at` / `end_at` | 活动期 |
| `channel` | 适用渠道（all / wecom / xhs） |
| `status` | active / ended |

## 操作步骤

### 1. 创建满减规则

**接口**：`crm_full_reduction.Create`

```json
{
  "name": "618 大促满减",
  "tiers": [
    {"threshold": 500, "reduction": 50, "max_reduction_count": -1},
    {"threshold": 1000, "reduction": 120, "max_reduction_count": -1},
    {"threshold": 3000, "reduction": 500, "max_reduction_count": 1000}
  ],
  "start_at": "2026-06-01",
  "end_at": "2026-06-18"
}
```

**字段说明**：
- `threshold`：满 X 元
- `reduction`：减 Y 元
- `max_reduction_count`：-1=不限，否则为限免次数（防羊毛党）

### 2. 订单核销（核心）

**接口**：`crm_order.Create` 时自动触发 `crm_full_reduction.Match`

```go
1. 取订单 amount
2. 查所有 active + 时间范围内 + channel 匹配的满减规则
3. 按 threshold 排序，从高到低试
4. 匹配第一个满足 amount >= threshold 的：
   reduction = min(rule.reduction, rule.max_reduction_count)
5. 订单 coupon_amount += reduction（与优惠券叠加）
6. 标记 max_reduction_count - 1（如果有限）
```

### 3. 编辑/删除

**接口**：`crm_full_reduction.Update / Delete`

## 阶梯示例

```
订单 800 元 → 命中"满 500 减 50" → 实付 750
订单 1200 元 → 命中"满 1000 减 120" → 实付 1080
订单 5000 元 → 命中"满 3000 减 500"（限 1000 次） → 实付 4500
```

## 与优惠券关系

满减与优惠券**可以叠加**（按产品设计）：
- 先用满减 → 再用优惠券
- 或反过来（**待产品确认**）

## 注意事项

- **优先级**：通常阶梯高的优先（threshold 高）。
- **限免次数**：`max_reduction_count` 是单活动维度，**非单客户**（如需单客户维���需扩展）。
- **库存联动**：满减不消耗库存，但可能需与优惠券/秒杀组合。
- **跨租户禁止**。

## 当前限制（**产品补强点**）

- 无单客户维度限免（防同一客户多次满减）。
- 无"满件减"（按数量）。
- 无品类限制（指定商品参与）。
