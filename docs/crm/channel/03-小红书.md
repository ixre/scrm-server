# 小红书获客接入

本页按当前仓库代码描述。项目提供内部标准事件接收协议；实际平台或获客服务商的权限、事件格式和签名规则必须联调，不能把本文当作小红书官方接口文档。

## 当前已实现链路

`app/callback/xhs_http.go` 在配置的 `XhsCallbackPort`（缺省 9004）接收 `/xhs/callback/:app_id`。渠道配置须为 `xiaohongshu`、启用且匹配 `app_id`；请求携带 `X-Signature`，按原始 JSON 和配置的 CallbackToken 验证 HMAC-SHA256。请求体最多 1 MiB。配置凭据应通过现有渠道配置功能保存，不写进日志或文档。

外层为 `event_type` 和 `data`。当前支持：

| event_type | data 主要字段 | 结果 |
| --- | --- | --- |
| lead | `event_id`, `ext_user_id`, `nickname`, `mobile`, `form_id`, `content`, `happened_at` | 建立/复用客户与渠道身份、记录留资互动、创建人工引流任务 |
| comment / dm | `event_id`, `ext_user_id`, `nickname`, `content`, `ext_ref`, `happened_at` | 建立/复用客户与渠道身份、记录互动；提交后运行现有敏感词检查 |

`event_id` 位于 `data` 内，应传上游稳定事件 ID；`happened_at` 为秒级时间戳。租户和应用身份取自路径及服务端配置，不信任客户端指定租户。互动类型保存为 `lead/comment/dm`，使用 `CrmChannelInteraction.action_type/ext_ref/happened_at`。

## 一致性与重试

客户、`ChannelLink`、互动和引流任务在同一事务写入，任一失败全部回滚，回调返回失败供上游重试。相同租户和外部客户身份串行处理，互动有租户级唯一事件指纹；重放已处理事件不会新增记录或重新打开已完成任务。

没有稳定 `event_id` 时，按应用、外部客户、动作、业务引用、事件时间、内容和手机计算指纹。该兼容方式无法区分这些字段完全相同的两次真实互动，因此接入验收应提供稳定事件 ID。迁移前互动的事件键为空，不能追溯保证其重放去重；旧客户和引流任务仍按业务身份查重。

客户合并后的回调优先沿 `ChannelLink` 找主客户，避免重新创建被合并客户。存在冲突映射或映射客户已删除时返回错误，需先人工修复归属或恢复客户。新客户进入公海；补全姓名/手机只填空值，不覆盖销售已维护的信息。

## 未作为交付承诺的能力

本轮未实现 OAuth 授权流程、笔记列表同步、点赞收藏同步、平台标签回写、自动私信回复或真实企微加好友。旧文档中的 `crm_xhs.TrackInteraction/ListNotes/TagCustomer` 和通用 `dispatch.Send` 不能作为现有可调用接口。对外发送能力须逐渠道核实实现、权限和实际返回后验收。

## 验证

`app/services/crm_channel_task_test.go` 覆盖并发留资去重、写入失败完整回滚、失败重试、停用配置拒绝和合并身份复用；回调测试覆盖缺失签名拒绝。仍需使用真实接入方凭据验证签名、事件协议、重试策略及延迟。

### 新客户归属（0020）

首次建档可匹配已明确开启执行的客户分配规则，按来源/优先级选择规则并轮询或随机选择有效销售，遵守公海客户持有上限。客户、外部身份、互动、分配日志、轮询位置及引流任务保持同事务；引流任务继承新负责人。重复事件及已有映射客户不重新分配。无人可接收时留在公海，并在系统设置的执行记录中显示原因。旧规则默认不执行；此实现不等于真实平台协议已联调通过。
