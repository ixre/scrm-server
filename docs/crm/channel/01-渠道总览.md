# 渠道总览

## 目的
抽象多渠道适配层，让业务层（CRM）不感知渠道差异。

## 入口
- 工作台 → 系统设置 → 渠道接入
- 适配器注册中心

## 适配器模式

每个渠道（企微/小红书/公众号/抖音）实现统一的 `Adapter` 接口，业务层通过 `dispatch` 路由到对应适配器。

```
业务调用：dispatch.Send(channel, to, content)
        │
        ▼
dispatch 查 channel → 找到 adapter
        │
        ▼
adapter.SendMessage(to, content)
        │
        ▼
调用渠道 API（微信开放平台 / 小红书开放平台 / 字节开放平台）
```

## Adapter 接口定义

```go
type Adapter interface {
    Channel() string                                    // 渠道常量
    SendMessage(to ChannelUserID, content Message) error
    SendGroupMessage(groupID string, content Message) error
    GetUserInfo(channelUserID ChannelUserID) (*UserInfo, error)
    HandleWebhook(payload []byte) ([]Event, error)
    GetAuthURL(redirect string) string                  // OAuth 授权
    ExchangeCode(code string) (*Token, error)
}
```

## 客户接入流程（统一）

```
客户扫码/搜索/点击 → 渠道回调 → Adapter.HandleWebhook
        │
        ▼
解析出 channel_user_id → 查 CrmChannelLink
        │
        ├── 找到 → 关联到现有客户
        └── 找不到 → 创建 CrmCustomer + CrmChannelLink
```

## Webhook 异步化

每个渠道的回调（消息/事件）通过 webhook 接入：

```
用户操作 → 渠道侧 API → 回调我方 /webhook/{channel}
        │
        ▼
Adapter.HandleWebhook 解析事件
        │
        ▼
dispatch.Call(channel, event_type, payload)
        │
        ▼
业务 Handler 处理（存 CrmChannelInteraction / CrmCustomer 等）
```

## 多渠道客户标识

每个客户可有多个 `CrmChannelLink`：

```
CrmCustomer (id=100, name=张三)
   ├─ CrmChannelLink (channel=wecom, channel_user_id=ext_xxx, is_primary=true)
   ├─ CrmChannelLink (channel=xiaohongshu, channel_user_id=xhs_yyy, is_primary=false)
   └─ CrmChannelLink (channel=gzh, channel_user_id=openid_zzz, is_primary=false)
```

通过 `ChannelLink` 反查客户时按 `is_primary DESC` 排序。

## 注意事项

- **统一 ID**：CrmCustomer.id 是本地主键，**不依赖任何渠道 ID**。
- **主渠道**：同一时间仅 1 个 `is_primary=true`（**当前未实现主渠道切换审计**）。
- **OAuth**：每个渠道都需要单独接入 OAuth，获取 access_token。
- **token 刷新**：access_token 通常 2h 过期，**需定时刷新**。

## 当前限制（**产品补强点**）

- 无视频号接入（仅可复用企微部分能力）。
- 无渠道账户矩阵（同一企业多账号管理）。
- 无渠道故障转移。
