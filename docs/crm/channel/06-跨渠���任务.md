# 跨渠道任务

## 目的
通过统一接口向多个渠道发消息、做 SOP、做群发。

## 入口
- 工作台 → 营销中心 → 群发任务
- SOP 配置时选择多渠道

## 核心：Dispatch 注册中心

`internal/dispatch/crm.go`：

```go
func Send(channel, to, content) error {
    adapter := GetAdapter(channel)
    return adapter.SendMessage(to, content)
}
```

注册总数：645 个分发函数，覆盖 157 个 unique domain。

## 操作步骤

### 1. 跨渠道群发

**接口**：`crm_mass_msg.SendToMultipleChannels`

```json
{
  "audience": {
    "tag_filter": ["VIP客户"],
    "channels": ["wecom", "xiaohongshu", "gzh"]
  },
  "content": {
    "text": "618 大促开始啦～",
    "image": "https://cdn.example.com/618.jpg",
    "link": "https://example.com/promo"
  }
}
```

**逻辑**：

```go
1. 查询客户：tag_filter 命中 + 至少有一个 channel 在 channels 列表中
2. 对每个客户：
   找到 is_primary=true 的 channel_link
   如果 channel_link.channel 在目标 channels 中 → dispatch.Send
3. 写入 CrmMassMsgLog（每条发送一条记录）
```

### 2. 跨渠道 SOP 触发

SOP 触发时可指定多渠道动作：

```json
{
  "trigger_type": "new_customer",
  "actions": [
    {"type": "send_message", "channel": "wecom", "content": "..."},
    {"type": "send_message", "channel": "gzh", "content": "..."}
  ]
}
```

**逻辑**：每个 action 独立 dispatch 到对应渠道。

### 3. 跨渠道客户合并

**接口**：`crm_channel_link.Merge`

场景：同一客户在小红书和企微分别留资，需要合并为同一个本地客户：

```go
1. 客户 A（小红书）和客户 B（企微），��机号相同
2. 选 A 为主客户
3. 将 B 的 channel_link 转移到 A
4. B 标记 status=merged
5. 合并跟进记录/订单/工单
```

### 4. 跨渠道客户视图

**接口**：`crm_channel_link.ListByCustomer(customerID)`

返回客户所有渠道链接，便于在客户画像展示。

## 跨渠道群发限制

| 限制 | 说明 |
|------|------|
| 单次上限 | 1000 人（**待产品确认**） |
| 频控 | 同一客户 1 天最多 X 条（**当前未实现**） |
| 内容一致 | 不同渠道内容需适配（如小红书无模板消息） |

## 注意事项

- **主渠道**：默认按主渠道发送，客户未关注主渠道时**回退到次渠道**。
- **跨渠道优先级**：企业微信 > 公众号 > 小红书 > 抖音（产品定义，**待产品确认**）。
- **失败重试**：单渠道发送失败不影响其他渠道，**当前未实现自动重试**。

## 当前限制（**产品补强点**）

- 无渠道频控（防骚扰）。
- 无统一发送状态聚合查询。
- 无 A/B 测试（同一活动不同渠道对比）。
