# 跨渠道引流任务

## 用户任务与入口

销售在“引流任务”查看小红书留资客户，联系客户并记录是否完成添加企微等工作；主管分配或重新打开任务，并查看操作记录。此模块记录人工处理，不会自动添加企微好友，也不是跨渠道群发接口。

新留资在同一事务中创建客户、渠道身份、互动和引流任务。已有有效客户负责人时分给该负责人；新客户进入公海，须先完成客户领取，再在任务页领取任务。重复回调不会重建已完成或软删除的任务。历史重复任务及合并客户原有任务保留，需主管按实际结果处理。

## 状态与权限

| 状态/动作 | 业务规则 |
| --- | --- |
| pending | 待处理，创建后 48 小时到期 |
| timeout | 已超时但仍可领取、分配、完成或跳过；每小时扫描，每批 200 条，单轮最长 2 分钟 |
| done / skipped | 终态，必须记录 1–512 字结果或原因；记录处理人、处理时间 |
| 领取 | 当前客户负责人可领取，包括接回共享成员持有的任务；记录原/新负责人，不转移客户 |
| 分配 | 管理员/经理操作，仅可选择同租户有效且为当前客户负责人/共享成员的员工；候选支持搜索，单次最多 100 人 |
| 重新打开 | 管理员/经理说明原因，将完成/跳过任务改为待处理，重新计 48 小时；保留原处理日志 |

销售仅可见自己当前负责客户的任务，或分配给自己且仍有共享权限的客户任务；完成/跳过须为任务接收人。管理员/经理可管理本租户任务。公海、黑名单、交接中或已删除客户的任务不能继续操作。当前客户权限同时约束历史记录访问。

所有修改带 `version`，过期版本拒绝覆盖；相同处理人重复提交相同完成/跳过结果幂等。状态与审计在同一事务提交。

## 实际接口

注册于 `internal/dispatch/crm.go`，服务为 `crm_channel_task`：

| 方法 | 参数 |
| --- | --- |
| List | `page`, `page_size`, 可选 `status`；兼容旧 `pager` / `query.status` |
| Assignees | `id`, 可选 `keyword`；仅管理员/经理 |
| Claim | `id`, `version` |
| Assign | `id`, `user_id`, `version` |
| MarkDone / MarkSkipped | `id`, `version`, `note` |
| Reopen | `id`, `version`, `note` |
| Logs | `id`, `page`, `page_size` |

列表返回客户名/电话、负责人、截止时间、处理结果与 `can_claim/can_assign/can_resolve/can_reopen`。前端按能力显示按钮，服务端仍独立校验权限；不能以隐藏按钮代替鉴权。日志分页返回创建、领取、分配、超时、完成、跳过和重新打开记录。

## 数据和升级

`crm_channel_task` 增加截止/处理时间、处理人、结果、版本和幂等键；`crm_channel_task_log` 保存操作轨迹。迁移 `0017_channel_task_workflow.sql` 保留历史任务，缺失截止时间按创建时间加 48 小时补齐，不编造历史操作人或日志。旧任务不强制填入唯一事件键，不自动删除重复历史数据。

索引覆盖租户/接收人/状态、客户任务去重、到期任务扫描、日志时间线和渠道身份；不新增物理外键。列表仍使用有上限的分页及总数统计，深分页和千万行权限查询需按真实租户分布压测。

部署顺序：备份并验证副本 → 执行版本迁移 → 同步部署 backend 和 dashboard。旧前端缺少 `version/note`，不能继续提交状态变更。

## 验收边界

数据库回归覆盖权限、并发、事务回滚、重试、客户合并、分页和历史迁移。尚未完成真实小红书账号联调；当前固定时限、手动领取和指定人员分配不等于可配置 SLA、通用规则分配或对外自动触达。
