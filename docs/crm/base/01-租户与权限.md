# 租户与权限

## 目的
多租户 SaaS 隔离 + 员工/角色权限控制 + 平台管理（套餐/支付/订单）。

## 入口
- 平台管理 → 租户列表（平台超管，独立登录入口）
- 企业管理 → 权限管理（租户内角色管理）

## 数据模型

### Tenant（租户）

`models/crm.go`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 租户 ID（id_generator 生成） |
| `name` | string | 企业/组织名称 |
| `code` | string | 租户编码（唯一索引） |
| `status` | int | 1-启用 2-停用 |
| `plan` | string | 套餐：free / trial / standard / pro / enterprise |
| `expire_at` | *time.Time | 套餐到期时间（NULL=永久） |
| `contact_name` | string | 联系人姓名 |
| `contact_phone` | string | 联系人手机 |
| `contact_email` | string | 联系人邮箱 |
| `industry` | string | 所属行业 |
| `logo` | string | 企业 Logo URL |
| `max_users` | int | 最大用户数（0=不限） |
| `max_customers` | int | 最大客户数（0=不限） |

### PlatformAdmin（平台超管）

`models/crm.go`：独立于租户，管理所有租户。不归属任何 tenant，专用登录入口，JWT 标记 `is_platform`。

| 字段 | 说明 |
|------|------|
| `username` | 登录名（全局唯一） |
| `password` | 登录密码（哈希） |
| `name` | 显示名 |
| `role` | 平台角色：super_admin / operator / finance / support |
| `status` | 1-启用 2-停用 |

### CrmRole（角色）

`models/crm.go`：CRM 原生权限模型，tenant 分区。本地 `User.role_id` 引用本表。

| 字段 | 说明 |
|------|------|
| `tenant_id` | 归属租户 ID |
| `code` | 角色编码（admin / manager / sales） |
| `name` | 角色名称 |
| `perms` | 权限点编码数组（jsonb） |
| `is_default` | 是否默认角色（新用户自动分配） |

## 平台管理功能

平台超管登录后可管理以下资源（均需 `requirePlatformAdmin` / `requirePlatformRole` 校验）：

| 模块 | dispatch 接口 | 说明 |
|------|--------------|------|
| 租户管理 | `crm_tenant.Create/List/ListPaged/GetDetail/Update/SetStatus/Delete/Renew/ResetAdminPassword` | 创建/查询/更新/停用/删除租户 |
| 套餐管理 | `crm_plan.Create/List/Update/SetStatus/Delete/Get/ListModules` | 套餐定义与功能模块 |
| 支付方式 | `crm_payment_method.*` | 平台端支付配置 |
| 订单管理 | `crm_order.ListAll/ManualConfirmPay` | 平台端订单查看与手动确认 |
| 租户端订单 | `crm_tenant_order.Create/List/Get/QueryPayStatus/GetQrCode/Cancel/ListPaymentMethods` | 租户下单购买套餐 |
| 平台操作日志 | `PlatformOperationLog` 模型 | 记录超管对租户/套餐/支付等操作 |

## 操作步骤

### 1. 创建租户（平台超管）

**接口**：`crm_tenant.Create`（需 super_admin / operator 角色）

```json
{
  "name": "Acme 公司",
  "code": "acme",
  "plan": "pro",
  "expire_at": "2027-08-18",
  "admin_username": "admin",
  "admin_name": "管理员",
  "admin_mobile": "13800138000"
}
```

创建租户时事务内一并种子默认角色（admin/manager/sales）、销售阶段，并创建该租户的管理员账号（`User`）。`admin_password` 为空时生成随机初始密码并返回。

### 2. 角色管理

**接口**：`crm_role.Create / List`（租户内角色管理，通过 CrmRole 模型）

> 注：当前 CRM 原生角色管理接口尚未在 dispatch 中独立注册，角色通过 `seedTenantDefaults` 自动种子。企微域角色管理走 `role.Create/Query/AssignToStaffs`。

**预设角色**（`defaultRoles`，创建租户时自动种子）：

| code | name | 权限点 |
|------|------|--------|
| `admin` | 租户管理员 | 用户管理/风控/营销/SOP/智能名片 |
| `manager` | 销售经理 | 用户创建/风控/营销/SOP/智能名片 |
| `sales` | 销售（默认） | 智能名片 |

### 3. 员工授权

**接口**：`crm_role.Assign`（标注：待实现，当前通过 `User.role_id` 关联 `CrmRole`）

企微域员工授权走 `role.AssignToStaffs`。

### 4. 数据权限

权限校验通过后端 dispatch 的 `requireRole` / `requireAnyRole` 函数实现（如 `requireAnyRole(ctx, "admin", "manager")`）。

| 角色 code | 含义 |
|----------|------|
| `admin` | 租户管理员（全部业务） |
| `manager` | 销售经理 |
| `sales` | 销售（仅自己） |

## 权限校验机制

权限通过**前端 authority 配置 + 后端 dispatch 校验**实现：

- **前端**：根据 `User.role_id` 对应的 `CrmRole.code` 控制菜单/按钮可见性。
- **后端**：dispatch 层通过 `requireRole(ctx, code)` / `requireAnyRole(ctx, codes...)` 校验角色编码（fail closed：无角色/角色不存在一律拒绝）。平台管理 API 通过 `requirePlatformAdmin` / `requirePlatformRole` 校验。

> 注：不存在独立的 `middleware/rbac.go` 中间件文件，权限校验内嵌在 dispatch handler 中。

## 多租户隔离

通过 GORM Scopes 自动注入 `tenant_id` 条件。核心函数 `models.TenantScope(tenantID)`：

- `tenantID` 非空：追加 `WHERE tenant_id = ?`
- `tenantID` 空字符串：不追加（用于跨租户运维：seed / tasks / consumers / callback）

业务层通过 `models.MustFor(ctx)` 获取自动绑定 ctx 租户的 `*gorm.DB`，或显式 `Scopes(models.TenantScope(tenantID))`。

> 注：不存在独立的 `db/tenant.go` 文件，租户隔离逻辑在 `models/tenant_scope.go` 中实现。

## 注意事项

- **越权防护**：所有 SQL 必须带 `tenant_id`，**通过 GORM Scopes 自动注入**。
- **角色变更**：员工调岗时**及时更新角色**。
- **平台超管**：独立登录入口，JWT 标记 `is_platform`，与租户内 User 解耦。
- **无 ctx 路径**：seed/tasks/consumers/callback 等无 ctx 场景必须保留裸 DB，靠 ChannelLink 反查租户。

## 当前限制（**产品补强点**）

- 无字段级权限（同一菜单下不同字段可见性不同）。
- 无 ABAC（基于属性的权限）。
- CRM 原生角色管理接口（`crm_role.*`）尚未在 dispatch 独立注册，角色靠种子自动创建。
