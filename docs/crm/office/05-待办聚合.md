# 待办聚合

## 目的
将各模块的待办（跟进/审批/工单）聚合到统一入口。

## 入口
- 销售管理 → 跟进待办 → 待办中心

## 数据模型

### Todo（待办）

| 字段 | 说明 |
|------|------|
| `staff_id` | 待办所属员工 |
| `biz_type` | 业��类型（followup / approval / workorder / report） |
| `biz_id` | 业务对象 ID |
| `title` | 标题 |
| `due_at` | 截止时间 |
| `status` | pending / done / overdue |
| `priority` | high / normal / low |

## 操作步骤

### 1. 查询我的待办

**接口**：`crm_todo.Query(staffID, status)`

聚合：

```go
1. followups = CrmFollowup WHERE owner=staffID AND status=pending
2. approvals = Approval WHERE approver=staffID AND status=pending
3. workorders = Workorder WHERE assignee=staffID AND status!=closed
4. reports_due = WorkReport WHERE staff=staffID AND period_end < today AND submitted=false
5. 合并 + 排序（按 due_at ASC）
```

### 2. 标记完成

**接口**：`crm_todo.Handle(bizType, bizID)`

完成后回到对应业务模块标记（如跟进标完成、审批通过）。

### 3. 截止前提醒

**定时任务**：

```go
每天早上 9 点扫描：
- 当天到期的待办 → 推送企微消息
- 已逾期的待办 → 升级通知主管
```

## 待办来源

| biz_type | 来源 | 跳转 |
|----------|------|------|
| followup | CrmFollowup | 跟进详情 |
| approval | Approval | 审批详情 |
| workorder | Workorder | 工单详情 |
| report | WorkReport | 工作报告 |
| lead_assign | Lead | 线索详情 |
| aftersale | Aftersale | 售后详情 |
| contract | Contract | 合同详情 |

## 工作台首页示例

```
【今日待办】
├── [跟进] 张三到期回访（10:00）
├── [审批] 折扣申请待批（2h）
├── [工单] 客户投诉待处理
└── [报告] 周报未提交

【逾期未处理】
└── [跟进] 李四回访已逾期 3 天
```

## 注意事项

- **多源聚合**：同一业务可能产生多个 todo（**当前是各业务自治**）。
- **删除**：业务完成后 todo 自动消失。
- **超时升级**：超时未处理可自动转给上级（**当前未实现**）。

## 当前限制（**产品补强点**）

- 无智能排序（按重要性）。
- 无日程视图（按日期日历展示）。
- 无团队待办汇总（主管视角）。
