# 流失告警与超时

## 目的
及时识别已流失 / 即将流失 / 超时未跟 / 超时未回的客户。

## 入口
- 工作台 → 风险告警中心
- CRM 客户列表筛选 `out_flow_status=1`

## 数据模型

### CrmCustomerLoss（流失记录）
`models/crm.go:640-651`：

| 字段 | 说明 |
|------|------|
| `customer_id` | 客户 ID |
| `user_id` | 原归属销售 |
| `loss_type` | deleted（被删）/ unfollowed（长期未跟）/ churned（流失） |
| `days` | 未跟天数 |
| `status` | pending / handled |

### CrmReplyTimeout（超时未回复）
`models/crm.go:654-664`：

| 字段 | 说明 |
|------|------|
| `user_id` | 应回复销售 |
| `customer_id` | 客户 |
| `channel` | 渠道 |
| `last_msg_at` | 客户最后消息时间 |
| `timeout_mins` | 超时分钟数 |
| `status` | pending / replied / escalated |

## 操作步骤

### 1. 查看流失告警列表

**接口**：`crm_customer_loss.List`

```json
{
  "loss_type": "unfollowed",
  "status": "pending"
}
```

返回流失客户列表 + 分页。

### 2. 处理流失告警

**接口**：`crm_customer_loss.Handle`

```json
{
  "ids": ["1001"],
  "status": "handled"
}
```

处理动作：可同时做"重新跟进 / 入公海 / 拉黑"。

### 3. 自动检测长期未跟（定时任务）

**文件**：`tasks/crm_automation.go:174-195`

**触发**：每小时执行一次。

**逻辑**：

```sql
INSERT INTO crm_customer_loss (tenant_id, customer_id, loss_type, days, status)
SELECT c.tenant_id, c.id, 'unfollowed', 
       EXTRACT(DAY FROM (now() - c.updated_at))::int, 'pending'
FROM crm_customer c
WHERE c.pool_status = 0 AND c.is_blacklist = false AND c.is_locked = false
  AND c.updated_at < now() - INTERVAL '30 days'
```

**注意**：
- 当前仅按 `updated_at > 30d` 一种场景。
- **产品补强点**：未覆盖"订单下降""投诉""沉默天数分桶"。

### 4. 流失客户标记

**接口**：`crm_wecom.MarkWecomCustomerLost(tenantID, corpID, customerExtID)`

**触发**：企微回调"删除外部联系人"事件。

**逻辑**：
- 客户 `out_flow_status = 1`
- 写 `CrmCustomerLoss` (loss_type='deleted')
- 客户进入"已流失"列表

### 5. 查看超时未回复

**接口**：`crm_reply_timeout.List`

```json
{
  "status": "pending"
}
```

### 6. 处理超时未回复

**接口**：`crm_reply_timeout.Handle`

把状态置为 `replied` 或 `escalated`（升级到主管）。

### 7. 自动检测超时未回复（定时任务）

**文件**：`tasks/crm_automation.go` + `services/crm_risk.go:290-346`

**逻辑**：每 30 分钟扫描。

```sql
INSERT INTO crm_reply_timeout
SELECT ... FROM chat_msg m
WHERE m.direction = 'in' AND m.reply_status = 'pending'
  AND m.msg_time < now() - INTERVAL '30 minutes'
```

### 8. 配置超时阈值

当前：固定 30 分钟。建议后续在 `CrmCustomerSetting` 增加 `reply_timeout_minutes` 字段。

## 告警类型总结

| 类型 | 触发条件 | 处理建议 |
|------|---------|---------|
| 流失-已删 | 企微删好友 | 不再触达 |
| 流失-未跟>30d | 长期未跟 | 重新激活或入公海 |
| 流失-订单下降 | 订单金额下降 N% | 主动关怀（待实现） |
| 超时未回-30min | 客户发消息 30 分钟未回 | 立刻回复 |
| 超时未回-2h | 客户发消息 2 小时未回 | 主管介入 |

## 注意事项

- **流失≠拉黑**：流失客户可重新激活，拉黑客户永久屏蔽。
- **告警聚合**：建议工作台首页展示"待处理告警数"。
- **批量处理**：可批量置为 handled，提升效率。
- **统计指标**：流失率 = 流失客户数 / 总客户数。
