# 客户公海与池

## 可用流程

销售可浏览公海、查看客户基本资料并认领；管理员和经理可将公海客户分配给有效的本租户销售。认领/分配会检查客户当前状态、黑名单、持有上限；前负责人自行认领还受冷却期限制。同一销售的并发领取串行校验额度，整批失败不会部分分配。

公海包含显式 `pool_status=1` 的客户，也包含历史导入中 `pool_status=0`、负责人为空且不在交接中的客户。客户创建未指定销售时默认归当前操作人；需要入公海应显式提交 `pool_status=1`。渠道留资按各渠道流程进入公海，不能把所有无负责人输入都解释为自动入海。

`crm_pool.Get` 专门读取当前公海客户的主档。客户已被其他销售领取后，该接口拒绝继续读取，页面提示刷新；普通客户详情权限保持原有的负责人/共享/管理者范围。公海基本资料可查看不代表授予全部跟进、合同和财务权限。

## 接口约定

- `crm_pool.List`：GET 查询参数 `keyword/page/page_size`，网关组装为 `query/pager`。返回列表和总数。
- `crm_pool.Get`：POST `{id}`，返回当前公海客户主档。
- `crm_pool.Claim`：POST `{ids}`，认领人为当前登录销售。
- `crm_pool.Assign`：POST `{ids,target_user_id}`，仅管理员或经理执行。
- `crm_pool.Recycle`：POST `{ids}`，回收当前有权操作的客户，排除锁定和交接中客户，清除负责人和共享权限并记录前负责人。
- `crm_pool.GetRule / SetRule`：读取/保存租户单条公海规则。只有管理员可保存，HTTP 与服务层都校验；首次并发保存采用原子 upsert，不产生重复规则。前端普通销售、经理仅查看。
- `crm_pool.ListLogs`：POST `{customer_id?,pager:{page,page_size}}`；前端已修正此前平铺分页参数不生效的问题。
- `crm_pool.GetStats`：公海总量及今天认领/回收/分配数；日志数按当前可见范围统计，数据库失败会返回错误。

## 规则语义

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否执行定时自动回收；不控制人工认领额度 |
| `recycle_days` | 超过指定天数未跟进，0 关闭此条件 |
| `no_deal_days` | 超过指定天数且无进行中商机、无已签约/完成合同，0 关闭此条件 |
| `claim_limit` | 单销售持有客户总数上限，0 不限；认领与管理员分配均检查 |
| `claim_cooldown_days` | 前负责人再次自行认领的冷却天数，0 不限 |
| `protect_days` | 最近认领后的保护天数，0 不保护 |

天数允许 0 至 36500 的整数，持有上限允许 0 至 1000000。启用时至少指定一项非零回收天数。所有字段可保存为 0，关闭状态不会被默认值重新启用。

两项回收条件为“或”：已有签约合同只阻止未成单条件，不阻止独立启用的未跟进条件。未跟进基准取创建、最近认领、有效跟进中最新时间；未成单基准取创建与最近认领中较新时间。保护期、锁客、交接状态同时约束两项规则。软删除跟进、商机和合同不参与保护，其他租户的错误关联不参与判断。

## 自动回收与数据规模

调度按当前任务配置每日 02:00 执行，只处理启用且未到期租户。租户每批读取 100 个，每租户有 2 分钟执行期限；新增客户通过本轮起始 ID 上界留给后续运行。客户按 ID 游标、每批最多 200 条执行，使用 `SKIP LOCKED` 跳过正在操作的记录。获得锁后再次检查条件，客户修改与日志在同一批事务提交。

跟进、商机和合同采用带租户条件的存在性查询，不在应用层为每个客户分别发起查询；状态更新和日志批量写入。每批结束释放锁，规则禁用在下一批生效。数据库故障或超时时，当前批次回滚，已成功批次保留，错误日志记录已提交数量；后续运行继续处理仍符合条件的客户。被锁跳过的记录需下一次调度重试，不能承诺本轮全部回收。

迁移 `0019_pool_recycle_indexes.sql` 新增回收游标、有效商机及两类公海日志索引，无物理外键和数据回填。大租户仍需使用真实数据验证执行计划、回收延迟及写入成本；分页和批处理不等于通过千万行容量验收。

## 日志与权限

管理员/经理可读本租户全部公海日志；销售只能读当前公海、本人或共享客户的日志。客户被其他销售领取、交接或共享撤销后，下次查询不再返回相关私有历史。客户已删除的历史仅管理者可见；无权过滤客户返回空集合。今日操作统计遵循同样范围，不代表普通销售能查看全企业业绩。

## 验证与尚未交付

`crm_pool_safety_test.go` 覆盖规则越权及并发首存、私有日志与统计、当前公海详情、450 客户并发回收、审计失败整批回滚、重试、保护期、合同/商机和租户生命周期；既有 `TestPoolQuotaAndRecycleRegression` 继续验证认领额度竞争及冷却期。前端请求契约测试覆盖日志分页体和公海详情路由。

新获客规则已支持小红书及落地页首次新建客户的来源匹配、轮询/随机分配，需明确开启执行；客户持有上限与公海领取共用。无法分配时保留公海并记录原因，由主管人工处理。已有公海客户不会被新规则重新分配，独立线索、权重及复杂条件仍仅配置。详见 [CRM 总览](../README.md) 的新获客执行说明。真实浏览器流程、调度运行指标与生产容量压测仍需验收。
