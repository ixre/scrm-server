# 客户公海与池

## 目的
防止客户沉淀在离职/消极销售手里，通过"公海回收 → 重新分配"保持销售资源流转。

## 入口
- 客户管理 → 公海池
- 企业管理 → 系统设置 → 公海规则配置

## 数据模型

### CrmCustomer 公海字段
- `pool_status` 0/1：是否在公海
- `pool_at`：进入公海时间

### CrmPoolRule（公海规则）
`models/crm.go` 内置：
- `recycle_days`：未跟进天数阈值（默认 30）
- `enabled`：是否启用自动回收

### CrmAutoAllocation（自动分配规则）
`models/crm.go`：
- 新建客户后自动分配给谁
- 按"部门轮询 / 抢单 / 指定"

## 操作步骤

### 1. 配置公海规则

**接口**：`crm_pool.SetRule`

```json
{
  "recycle_days": 30,
  "enabled": true
}
```

### 2. 查看公海池

**接口**：`crm_pool.List(tenantID, keyword, pager)`

返回 `pool_status=1` 的客户列表，按 `pool_at desc` 排序。

### 3. 销售认领客户

**接口**：`crm_pool.Claim(tenantID, userID, customerIDs)`

```json
{
  "ids": ["1001", "1002"]
}
```

**逻辑**：
- 把客户的 `pool_status=0, owner_user_id=userID, pool_at=null`
- 触发 SOP `pool_claim` 事件

**前端入口**：
- 公海池页面 → 勾选客户 →「认领选中」按钮（批量认领）
- 公海池页面 → 每行「认领」按钮（单个认领）

### 4. 客户再分配（销售间转移）

**接口**：`crm_transfer.Transfer`

```json
{
  "customer_ids": ["1001"],
  "to_user_id": "201",
  "reason": "我即将离职"
}
```

**日志**：`CrmTransferLog` 记录 from/to/时间/原因。

### 5. 离职继承

**接口**：`crm_inheritance.Execute`

```json
{
  "from_user_id": "201",
  "to_user_id": "305",
  "inherit_type": "resign",  // transfer(在职) / resign(离职)
  "remark": "李四离职，客户转给王五"
}
```

**继承范围**：客户的客户主档 + 商机 + 跟进 + 工单 + 订单（如未完成）一并归属到新销售。

## 数据进入公海池的方式

公海池的数据来源共 5 种，覆盖手动、自动、创建、导入等场景：

### 方式 1：创建客户时不指定归属销售

**触发条件**：新建客户时 `owner_user_id` 为空（未选择归属销售）。

**后端逻辑**（`crm.go` → `CrmCustomerService.Create`）：
```go
if req.OwnerUserID == "" {
    req.PoolStatus = 1
    now := time.Now()
    req.PoolAt = &now
}
```

**前端入口**：
- 客户列表 →「新建客户」→ 归属销售留空 → 自动入公海
- 客户列表 →「新建客户」→ 勾选「放入公海池」开关 → 归属销售禁用并清空 → 自动入公海

### 方式 2：客户列表手动移入公海（单个）

**接口**：`crm_pool.Recycle(tenantID, customerIDs)`

**逻辑**：将 `pool_status=0` 的客户更新为 `pool_status=1, pool_at=now, owner_user_id=""`。

**前端入口**：
- 客户列表 → 操作列 →「移入公海」按钮（仅对 `pool_status=0` 的已分配客户显示）
- 点击后弹确认框，确认后调用 `CrmPoolRecycle([id])`

### 方式 3：客户列表批量移入公海

**接口**：`crm_pool.Recycle(tenantID, customerIDs)`

**前端入口**：
- 客户列表 → 勾选多个客户 → 顶部「批量移入公海」按钮
- 点击后弹确认框，确认后对选中的客户批量调用 `CrmPoolRecycle`

### 方式 4：自动回收（定时任务）

**接口**：`crm_pool.AutoRecycleAll`（遍历所有租户）→ `crm_pool.AutoRecycle`（单租户）

**触发**：定时任务调用。

**逻辑**（`crm_pool.go` → `AutoRecycle`）：
1. 读取租户公海规则 `CrmPoolRule`（`recycle_days` + `enabled`）
2. 若规则未启用或 `recycle_days <= 0`，跳过
3. 查所有 `pool_status=0` 且有归属的客户
4. 取每客户最新跟进时间 `lastFollowupTime`
5. 若最近跟进时间距今 > `recycle_days` 天，加入回收列表
6. 批量调用 `Recycle()` 移入公海

**注意**：无跟进记录的客户不会自动回收（`shouldRecycle` 返回 false）。

### 方式 5：批量导入无归属客户

**接口**：`crm_customer.BatchImport`

**逻辑**：批量导入客户数据时，若行数据中未指定 `owner_user_id`，则与方式 1 相同，自动设 `PoolStatus=1` 入公海。

**前端入口**：
- 客户列表 →「导入」按钮 → 上传 Excel/CSV → 无归属销售的行自动入公海

### 方式对比

| 方式 | 触发方 | 适用场景 | 频率 |
|------|--------|---------|------|
| 创建时不选归属 | 人工 | 新客户暂不确定归属哪个销售 | 日常 |
| 创建时勾选公海 | 人工 | 明确要放入公海供认领 | 日常 |
| 列表单个移入 | 人工 | 销售主动释放自己跟进不了的客户 | 日常 |
| 列表批量移入 | 人工 | 管理员清理长期未跟进客户 | 定期 |
| 自动回收 | 系统 | 超期未跟进客户自动流转 | 定时 |
| 批量导入无归属 | 人工 | 外部名单导入，暂不分配归属 | 批量 |

## 客户状态流转图

```
                     ┌─────────────────┐
                     │   新建/导入客户  │
                     └────────┬────────┘
                              │
                ┌─────────────┼─────────────┐
                │             │             │
           指定归属        不指定归属     勾选公海
                │             │             │
                ▼             ▼             ▼
         ┌──────────┐  ┌──────────────────────┐
         │ 销售在跟  │  │      公海池           │
         └────┬─────┘  └──────────▲───────────┘
              │                   │
              │ 主动释放           │ 自动回收(超期未跟进)
              │ 移入公海           │ 批量导入无归属
              │ 批量移入           │ 创建时不选归属
              └───────────────────┘
              │
              │ 转移/继承
              ▼
         ┌──────────┐
         │  新销售  │ ◄──认领─── 公海池
         └──────────┘
```

## 注意事项

- **无跟进不自动回收**：`shouldRecycle` 对无跟进记录的客户返回 false，靠手动回收或创建时入公海。
- **批量认领**：单次建议 ≤ 50 个，避免数据库压力。
- **审计**：转移操作写入 `CrmTransferLog`，可查历史。
- **共享 ≠ 转移**：共享保留原归属，转移变更归属。
- **公海池页面无回收按钮**：公海池列表都是 `pool_status=1`，回收操作只对 `pool_status=0` 生效，因此在公海池页面不提供回收功能。回收入口在客户列表页。
