# 客户去重与合并

## 目的
合并多渠道留资或手动录入产生的同一客户多条记录。

## 入口
- 工作台 → 客户管理 → 查重合并

## 数据模型
- `CrmCustomer` 主档
- `ChannelLink` 多渠道映射（4 渠道全覆盖）
- `CrmDedup` 服务

## 操作步骤

### 1. 按手机号查找重复客户

**接口**：`crm_dedup.FindDuplicates(tenantID, mobile)`

```json
{
  "mobile": "13800138000"
}
```

**返回**：该 mobile 下所有 `CrmCustomer` 列表。

**代码**：`services/crm_dedup.go:19-27`

```go
models.DB.Where("tenant_id = ? AND mobile = ?", tenantID, mobile).
    Order("created_at asc").Find(&cs)
```

### 2. 选择主客户 + 合并

**接口**：`crm_dedup.Merge(tenantID, primaryID, duplicateIDs)`

```json
{
  "primary_id": "1001",
  "duplicate_ids": ["1002", "1003"]
}
```

**合并流程**（`crm_dedup.go:31-97`）：

1. **校验**：所有客户同租户、primary 存在
2. **挑主**：`pickPrimary`（line 102-114）按"已成交 > VIP > 重点 > 最新"优先
3. **迁移 9 张关联表**：

```
CrmFollowup               // 跟进记录
CrmFollowupComment        // 跟进评论
CrmOpportunity            // 商机
CrmOrder                  // 订单
CrmReceivables            // 回款
CrmReceivablesPlan        // 回款计划
CrmWorkorder              // 工单
CrmAftersales             // 售后
CrmChannelInteraction     // 渠道互动
```

每张表：`UPDATE ... SET customer_id = primary WHERE customer_id IN duplicates`

4. **合并 ChannelLink**：duplicate 上的 ChannelLink 改 `entity_id = primary`
5. **合并客户属性**：非空字段覆盖到 primary
6. **合并 tags**：primary.tags + duplicate.tags 去重
7. **合并 remark**：拼接"--- [合并自 ID] ---"
8. **合并来源**：primary.source 保留，其余 append 到 remark
9. **软删 duplicate**：`UPDATE deleted_at = now()`

### 3. 合并冲突处理

**字段冲突**：`primary` 已有的字段不覆盖，duplicate 上的"非空 + primary 是空"的字段覆盖。

**注意**：
- `mobile` 全部一致才允许合并（同一手机号）
- `owner_user_id` 取 primary 的归属
- 重复客户均软删除，可通过 `CrmRecycle` 还原

## 与"客户转移"区别

| 操作 | 用途 | 客户数变化 |
|------|------|-----------|
| 去重合并 | 多条重复记录合并成 1 条 | N → 1 |
| 客户转移 | 把客户给其他销售 | 客户数不变 |

## 注意事项

- **合并不可逆**（除非走 CrmRecycle 恢复）
- **合并前建议先查 backup**：admin 可导出待合并客户清单
- **mobile 硬匹配**：目前不支持微信号/小红书 ID/群 ID 多规则合并（产品补强点）
- **合并日志**：当前未单独记合并日志表，建议加 `CrmMergeLog`
