# 跟进沟通

## 目的
记录销售与客户每次沟通的内容、结果、下一步行动，构建客户时间线。

## 入口
- 销售管理 → 跟进待办 → 待办中心
- 客户 360 详情页 → 写跟进

## 数据模型

### CrmFollowup（跟进记录）
`app/models/crm_customer_models.go`：

| 字段 | 说明 |
|------|------|
| `customer_id` | 关联客户；线索/商机跟进由服务端校验并补充关联 |
| `opportunity_id` | 关联商机（可空） |
| `user_id` | 跟进人 |
| `type` | call/visit/message/meeting/other |
| `content` | 跟进内容（文本） |
| `next_followup_at` | 下次跟进时间 |
| `contact_id` | 关联联系人（CrmContact） |
| `duration` | 跟进时长（分钟） |
| `result` | positive/neutral/negative |
| `next_action` | 下一步行动 |
| `location` | 签到位置（拜访时） |

### CrmFollowupComment（跟进评论）
`models/crm.go:1757-1764` 团队内部对跟进的评论/协作。

### CrmQuickFollowup（快捷跟进模板）
销售可预设 10-20 条常用跟进话术，输入关键字一键插入。

### CrmQuickRemark（快捷备注）
销售常用的快捷备注短语。

### CrmSignin（拜访签到）
`models/crm.go:1057-1068`：
- `latitude` / `longitude`：GPS 坐标
- `photos`：签到照片（JSONB）
- `address`：自动获取地址

## 操作步骤

### 1. 创建跟进

**接口**：`crm_followup.Create`

```json
{
  "customer_id": "1001",
  "opportunity_id": "2001",
  "type": "visit",
  "content": "客户对方案 A 很感兴趣，约周三再谈",
  "next_followup_at": "2026-08-20T10:00:00Z",
  "result": "positive",
  "next_action": "发送方案 A 详细文档",
  "duration": 45,
  "location": "上海市浦东新区..."
}
```

**副作用**：
- 更新客户 `next_followup_at`
- 客户当前预约由每 5 分钟调度生成提醒；新跟进会覆盖当前预约，未填写下一次时间则结束当前预约
- 客户评分可能上浮（按跟进次数）

### 2. 删除跟进

**接口**：`crm_followup.Delete`

**注意**：软删除，写 deleted_at。

### 3. 列出跟进

| Action | 用途 |
|--------|------|
| `crm_followup.ListByCustomer` | 按客户查 |
| `crm_followup.ListByOpportunity` | 按商机查 |

### 4. 写跟进评论

**接口**：`crm_followup_comment.Create`

```json
{
  "followup_id": "3001",
  "content": "@李四 这个客户对接的财务是王五，请同步告知。"
}
```

### 5. 快捷跟进

**接口**：`crm_quick_followup.Create`（管理个人模板）

```json
{
  "title": "首次电话",
  "content": "您好，我是 XX 公司 XX，请问方便聊一下吗？",
  "shortcut": "1"
}
```

**接口**：`crm_quick_followup.List`（拉取个人所有快捷跟进）

**使用方式**：前端展示模板列表 → 点击 → content 填入新建跟进表单。

### 6. 快捷备注

**接口**：`crm_quick_remark.Create / List / Update / Delete`

个人备注可新增、修改、删除及设置排序；共享备注可读取，仅管理角色可修改。共享归属在数据库为 NULL。编辑提交的 sort 与内容一起保存，数值越大越靠前。

### 7. 今日待办（关键工作流）

**接口**：`crm_followup_view.TodayTodo`

**逻辑**：按当前用户查自己的有效客户，当前预约时间早于明天零点（包含今日和逾期）。公海、黑名单和待接收交接客户不显示。早上跟进后又预约下午，下午预约仍需显示，不用“今天曾有跟进”排除客户。支持按客户名、手机、公司查询和分页；“从未跟进”使用数据库 NOT EXISTS 判断，不下载所有历史客户 ID。

前端跟进工作台显示 `name`、`next_followup_at`；快速跟进可同时填写下一次预约与下一步行动。今日已跟进按北京时间当日范围查询，包含 `customer_name`；客户已转交且当前无权查看时不展示旧记录内容。

**接口**：`crm_followup_view.TodayDone`

返回今天已完成的跟进（`CrmFollowup.created_at = today`）。

**接口**：`crm_followup_view.NeverFollowup`

返回从未跟进的客户（按建客时间倒序）。

### 8. 拜访签到

**接口**：`crm_signin.Create`

```json
{
  "customer_id": "1001",
  "latitude": 31.2304,
  "longitude": 121.4737,
  "address": "上海市黄浦区南京东路 100 号",
  "photos": ["https://.../1.jpg"],
  "remark": "面谈合同细节"
}
```

**用途**：外勤场景，校验销售真实到访。

## 跟进类型说明

| type | 适用场景 |
|------|---------|
| `call` | 电话沟通 |
| `visit` | 面对面拜访（可带 GPS + 照片） |
| `message` | 微信/企微/短信沟通 |
| `meeting` | 会议 |
| `other` | 其他 |

## 跟进结果字段

| result | 含义 |
|--------|------|
| `positive` | 客户积极响应 |
| `neutral` | 中性 |
| `negative` | 客户抗拒/拒绝 |

## 注意事项

- **阶段校验**：商机流转按租户销售规则检查近期跟进，见 `crm_sales_rule.go`。
- **预约可选**：需要后续行动时填写 `next_followup_at`；业务已结束时允许留空，不人为制造待办。
- **跟进评论权限**：默认仅本团队可见，可配置跨团队可见。
- **签到照片**：上传到对象存储（OSS/COS），注意大小限制（建议 ≤ 5MB）。
- **删除跟进**：仅创建人或管理员可删。
