# 客户主档操作流程

## 目的
建立和维护 CRM 客户主档，是销售开展业务的起点。

## 入口
- 工作台 → 客户管理 → 新建/列表
- 客户 360 详情页 → 编辑
- 渠道入站事件自动创建

## 数据模型

`CrmCustomer`（`models/crm.go:58-101`）核心字段：

| 字段 | 说明 |
|------|------|
| `name` | 客户名称（必填） |
| `mobile` | 手机号（按租户唯一索引） |
| `email` / `company` / `industry` / `position` | 基本信息 |
| `gender` / `birthday` / `address` | 拓展信息 |
| `level` | 客户等级 0-未知 1-潜在 2-普通 3-重要 4-重点 5-VIP |
| `source` | 来源渠道 wecom/xiaohongshu/manual/import/web_form |
| `owner_user_id` | 归属销售 ID |
| `next_followup_at` | 下次跟进时间（自动写入 CrmTodo） |
| `tags` | 客户标签（内部标签 ID 数组） |
| `ext_customer_id` / `ext_corp_id` | 渠道快照（企微 external_userid / 小红书 user_id） |
| `pool_status` | 公海状态 0-非公海 1-公海待认领 |
| `score` | 客户评分（0-100） |
| `is_locked` / `is_blacklist` / `is_key` | 锁客 / 黑名单 / 重点 |

## 操作步骤

### 1. 手动新建客户

**接口**：`POST /dispatch crm_customer.Create`

```json
{
  "domain": "crm_customer",
  "action": "Create",
  "data": {
    "name": "张三",
    "mobile": "13800138000",
    "company": "ACME",
    "industry": "互联网",
    "level": 2,
    "source": "manual",
    "remark": "朋友介绍"
  }
}
```

**代码**：`services/crm.go crmCustomerCreate`

**注意**：
- 同一租户内 `mobile` 唯一，重复会返回"客户已存在，请使用查重合并"。
- 自动生成 ChannelLink（渠道为 manual 时不创建）。
- 自动写 CrmCustomerSetting 校验（达到上限时禁止新建）。

### 2. 编辑客户

**接口**：`crm_customer.Update`

可修改字段（`crm.go:801 selectCols`）：

```
name, mobile, email, company, industry, gender, birthday,
level, address, owner_user_id, next_followup_at, remark, tags
```

**注意**：
- 改 `owner_user_id` 需走 `crm_customer_ext.ReassignByTransfer`，否则无转移日志。
- 改 `mobile` 需重新走查重校验。

### 3. 查询客户

| Action | 用途 |
|--------|------|
| `crm_customer.Get` | 按 ID 取详情 |
| `crm_customer.GetDetail` | 360 详情聚合（见 [08-客户画像360.md](08-客户画像360.md)） |
| `crm_customer.Query` | 分页列表 + 多条件过滤 |

`Query` 支持的过滤条件：
- `keyword`：模糊匹配 name / mobile / company
- `owner_user_id`：归属销售
- `source`：来源渠道
- `out_flow_status`：流失状态
- `pool_status`：公海状态

### 4. 删除客户

**接口**：`crm_customer.Delete`

**注意**：
- 默认走软删除（`gorm.DeletedAt`），30 天后回收站清理。
- 实际是写入 `CrmRecycle` 表，调用 `crm_recycle.Restore` 可还原。
- 真实删除走 `crm_recycle.DeleteRecord`。

### 5. 锁客 / 解锁

**接口**：
- `crm_customer_ext.Lock`（`crm_customer_ext.go:34`）
- `crm_customer_ext.Unlock`

**用途**：锁客防公海回收。例：销售在跟进中的客户锁 7 天不被自动入海。

```json
{
  "ids": ["1001", "1002"],
  "reason": "客户在报价谈判中"
}
```

### 6. 标记重点 / 共享

**接口**：
- `crm_customer_ext.SetKey(tenantID, ids, true)`：标记重点客户
- `crm_customer_ext.Share(tenantID, customerID, staffIDs)`：共享给其他销售

**共享** vs **转移**：
- 共享：保留原归属，附加可见人
- 转移：变更归属，旧销售不可见（除非共享）

### 7. 黑名单

**接口**：
- `crm_customer_ext.Blacklist(tenantID, ids, reason)`：拉黑
- `crm_customer_ext.RemoveBlacklist(tenantID, ids)`：解除
- `crm_customer_ext.ListBlacklist(tenantID, req)`：黑名单列表

**用途**：
- 黑名单客户不入公海
- 黑名单客户不可被新跟进
- 黑名单客户触发敏感词时自动告警

### 8. 再分配（交接班）

**接口**：
- `crm_customer_ext.ListReassign(tenantID, userID, req)`：待确认接收列表
- `crm_customer_ext.AcceptReassign(tenantID, userID, id)`：接受
- `crm_customer_ext.RejectReassign(tenantID, id)`：拒绝
- `crm_customer_ext.ReassignByTransfer(tenantID, from, to, ids)`：批量转移

**典型场景**：销售 A 调岗 / 离职后，B 接手 A 的客户。

## 渠道入站创建

四种渠道的 webhook 回调会自动创建客户（无需手动）：

```
企微    → POST /wecom/callback/:corp_id
小红书  → POST /xhs/callback/:app_id
公众号  → POST /gzh/callback/:app_id
抖音    → POST /douyin/callback/:app_id
```

**统一流程**：
1. webhook 接收事件（`app/callback/*_http.go`）
2. 走 `crm_wecom.go / crm_xhs.go / crm_gzh_douyin.go` 的 `SyncFromXxx` 方法
3. 查 CrmCustomer 按 mobile 去重（已存在则补全渠道快照）
4. 不存在则创建新 CrmCustomer + ChannelLink

**代码位置**：
- 企微：`services/crm_wecom.go SyncFromWeCom` (line 21)
- 小红书：`services/crm_xhs.go SyncFromXhs` (line 18)
- 公众号：`services/crm_gzh_douyin.go SyncFromGzh` (line 15)
- 抖音：`services/crm_gzh_douyin.go SyncFromDouyin` (line 166)

## 注意事项

- **手机号唯一**：同租户 mobile 唯一，导入或批量录入时需先查重。
- **租户隔离**：所有操作带 tenant_id，跨租户查询禁止。
- **渠道快照**：客户从多渠道触达时，每个渠道一条 ChannelLink，但客户主档只有一条。
- **删除谨慎**：物理删除需管理员权限，建议用"拉黑"代替删除。
- **归属变更**：用 `ReassignByTransfer` 而非直接 Update owner_user_id，以保留转移日志。
