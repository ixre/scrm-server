# 客户画像 360

## 当前入口与返回

客户管理打开客户详情，调用 `crm_customer.GetDetail`，参数为 `id`，租户和用户取登录身份。返回客户主档、最近 20 条企微单聊，以及跟进、非企微渠道互动、活动参与史、转移日志各最近 20 条。`history_pages` 按对应字段名返回 `has_more` 和 `next_cursor`。

详情与跟进弹窗显示“已加载 N 条”及查看更早记录入口，避免把页内数量误认为总量。客户切换、详情刷新或关闭后，旧请求不再覆盖当前内容。新增独立的“成交与回款”页展示报价、合同、计划和回款，商机可完整分页翻阅；这些业务记录没有混入客户动态时间线。工单仍未在此聚合。

## 历史分页协议

调用 `crm_customer.History`，参数：

```json
{"customer_id":"客户ID","kind":"followups","cursor":"","page_size":20}
```

`kind` 支持 `followups`、`activity_records`、`channel_interactions`、`transfer_logs`。响应为 `{items, has_more, next_cursor}`；下一页传回服务端返回的游标。每页默认 20 条、最多 100 条，按有效时间及 ID 倒序，不进行全部历史计数及深层 OFFSET 查询。活动/互动时间缺失时回退创建时间，均为空时使用固定历史时间，确保旧记录仍可翻阅。

游标绑定租户、客户和历史类别，不可跨范围复用。每次请求重新鉴权，权限被收回时旧游标也不能继续读取。连续翻页不会因列表顶部插入新记录而重复已有记录；新插入顶部记录需刷新后查看。该协议不是跨请求的数据库快照，修改历史排序时间可能改变记录位置。

旧 `crm_followup.ListByCustomer` 和 `crm_activity.ListByCustomer` 保留数组协议，但超过 1000 条时明确返回错误并提示使用新分页接口，避免无界读取或静默截断。所有调用方须处理错误，旧客户端应同步升级。

## 访问与写入边界

销售读取本人及共享客户，经理/管理员读取本租户客户。历史分页、转移历史、活动参与史和渠道互动查询分别校验客户权限，不依赖页面先鉴权。未传客户筛选时，互动列表也只返回可访问客户的数据。活动关联限定同租户并排除已删除活动资料，参与记录本身也排除软删除。

共享客户仅授予读取权限。人工新增和删除渠道互动须为当前客户负责人或经理/管理员；新增还要求客户已领取并完成交接。混合越权删除整批失败。客户归属或共享范围改变后，下次请求按最新权限判断。

企微消息必须同时匹配客户渠道身份和企业的租户映射；只填写外部企业/客户 ID 快照不足以获得存档访问。手工建档不能创建外部渠道身份，编辑不能改绑；这些身份由渠道同步维护。缺少有效映射时不展示存档。

## 本轮产品需求：客户成交与回款总览

销售在联系客户前，需要知道当前可见合同尚有多少未收、哪些回款计划需要核对，并能直接打开相关合同处理。改造前在客户详情无法完成这项任务，且商机页只装载前 50 条、名称字段错误。按 JTBD / MoSCoW，本轮优先补齐业务可见性、金额口径和历史翻阅；复杂分配、独立扩展产品继续分期。

验收标准：客户共享不自动授予其他销售合同和报价权限；金额仅统计当前可见的有效签约/完成合同，草稿、作废不混入应收；优惠券只扣一次，历史合同已收余额保留；回款计划按已确认且无需审批/已通过的关联回款核销，日期决定逾期，不依赖可能过时的状态；所有列表游标翻页，无前 50 条静默截断；打开合同继续回款，快速切换客户不串数据。权限、金额和分页均有自动回归，真实浏览器与大容量仍需实际验收。

本轮不伪造用户访谈和 RICE 覆盖人数。代码证据能证明功能缺口，不能替代用户满意度数据。上线后建议采集“打开客户到找到欠款合同的耗时”“从客户进入合同后成功登记回款的比例”“列表加载失败率”，当前尚未接入生产埋点。


## 成交与回款协议

`crm_customer.BusinessSummary` POST `{customer_id}` 返回 `signed_count`、`due_amount`、`paid_amount`、`outstanding_amount`、`overdue_plan_count`、`overdue_plan_unsettled` 与 `as_of`。金额为十进制字符串，避免大额汇总丢失分位。应收等于合同金额减优惠券，不再扣一次报价优惠；已收沿用合同余额，未收按每份合同分别计算后汇总，不能用一份超收冲抵另一份未收。只统计当前可见、未删除且状态为 signed/completed 的合同。

`crm_customer.BusinessRecords` POST `{customer_id,kind,cursor,page_size}`，`kind` 支持 `opportunities/quotes/orders/plans/receipts`，返回 `{items,has_more,next_cursor}`。默认 20、上限 100，ID 倒序，无总数计数或深层 OFFSET；游标绑定租户、客户和类别，每页重新鉴权。商机名称使用实际 `title`，报价使用 `subject`。合同、计划、回款记录可打开实际关联合同继续办理。

客户负责人或共享读取权仅控制客户入口；明细仍沿用各业务现有的负责人/签约销售和管理角色边界。没有可见业务时仅显示当前权限下为空，不透露不可见记录是否存在。回款与计划以同租户且未删除的父合同判定客户归属，不相信历史冗余 `customer_id`。合同作废后保留历史明细，汇总排除；草稿计划显示合同未签。

计划已核销只计 confirmed 且审批为 none/approved/空的关联回款，排除软删除、pending、void、待审及驳回。按计划 ID 和父合同 ID 一起求和，避免错误关联跨合同核销。计划日期早于中国时区今天且未核销金额大于 0 才标逾期；未关联计划的已收款不会自动分摊。逾期计划未核销不能等同于客户真实欠款总额，催款前需核对合同已收与计划关联。

汇总在单次只读一致性事务中完成，分页请求各有自己的快照；更新业务后可刷新汇总和记录。数据库错误或超时显示错误及重试入口，不返回假的零余额。每次请求最长 5 秒；真实容量副本应验证查询计划和耗时，不能把索引存在等同于千万行性能达标。
